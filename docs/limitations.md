# Limitations

## Evidence Scope

This repository provides benchmark and local RTL evidence for a tiny noisy temporal event-detection task. The evidence is useful for comparing candidate designs inside this benchmark, but it does not establish production hardware readiness.

The current milestone is:

- `tiny_snn_v2_sparse_activity` simulation passed.
- Synthesis evidence is available.
- Cell-count proxy: 610 cells.
- Cell ratio vs FSM: 3.961x.
- Toggle-count proxy: 73189 toggles.
- Toggle ratio vs FSM: 1.117x.
- RTL recommendation: `optimize_snn_rtl_before_more_features`.
- Research recommendation: `continue_snn_optimization`.
- Evidence manifest: complete with 0 missing outputs.

## What The Metrics Mean

Cell count is a synthesis proxy. It is a relative RTL complexity signal generated by the local synthesis flow.

Toggle count is a VCD activity proxy. It is a relative switching-activity signal generated from the local simulation vectors.

These values are useful for comparing designs that share the same benchmark, vectors, and tool flow.

## What The Metrics Do Not Mean

The current evidence does not claim:

- silicon area
- measured power
- measured energy
- gate-level power signoff
- physical design signoff
- timing closure
- foundry suitability
- production RFID tag integration readiness

The cell-count proxy should not be converted into silicon area without a technology library, constraints, and physical implementation context. The toggle-count proxy should not be converted into measured power or energy without characterized capacitance, timing, voltage, clocking, and implementation details.

## Benchmark Limits

The benchmark task is intentionally small. That is a strength for early feasibility work, but it also limits generalization.

The results should not be read as evidence that SNNs are broadly better or worse for RFID systems. They only say how these classifier families behave on this repository's noisy temporal event-detection scenarios.

The FSM and LUT baselines remain strong because the target motif is compact and fixed. A different workload with richer temporal structure, more channels, or less hand-designed state structure might change the balance.

## Toolchain Limits

RTL simulation, synthesis, and activity evidence depends on local tool availability. The pipeline currently expects tools such as Icarus Verilog and Yosys for full RTL evidence.

If those tools are missing, current-run RTL evidence is incomplete and stale RTL outputs are ignored. That behavior is intentional: an incomplete fresh run is more honest than silently reusing old generated artifacts.

The portable clean flow reduces platform-specific cleanup risk, especially on Windows, but it does not remove the need for a correctly configured RTL toolchain.

## Decision Limits

The current recommendation is conservative:

- Do not treat the sparse SNN as a final hardware winner.
- Do not add more RTL-facing features before reducing the SNN cell-count proxy.
- Do preserve the sparse SNN as the current baseline for further study.
- Do continue SNN optimization only when the next branch tests an architecture-level simplification.

Small local rewrites are not clearly justified unless they attack a measurable source of overhead. The next useful research question should explain why it might reduce cell count, toggle count, or both.
