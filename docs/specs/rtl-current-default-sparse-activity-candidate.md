# Feature Spec: RTL Candidate for current_default_sparse_activity

## Goal

Add a tightly scoped RTL feasibility branch for the best v2 temporal-hard software candidate:

```text
candidate_0154
weight variant: current_default_sparse_activity
competitive reason: activity_win_within_f1_tolerance
```

The generated v2 gate recommendation is:

```text
continue_to_snn_rtl_candidate
```

This does not mean SNN is proven better than FSM. It means the candidate is close enough in F1 and lower enough in software activity proxy to justify a bounded RTL feasibility check.

## Non-goals

Do not add:

- training,
- runtime-programmable weights,
- new SNN architectures,
- silicon power claims,
- silicon area claims,
- signoff claims.

This is only an RTL feasibility prototype for one fixed-weight candidate.

## Required RTL

Add a new module:

```text
rtl/snn/tiny_snn_v2_sparse_activity_detector.sv
```

It should use the same streaming interface as existing detectors:

```text
clk
rst_n
start
sample_valid
sample_bits
done
prediction
```

It should match the Python `tiny_snn_v2` behavior for the `current_default_sparse_activity` fixed-weight variant as closely as practical.

Do not replace `rtl/snn/tiny_snn_v2_detector.sv`. Keep the existing default RTL prototype unchanged.

## Candidate parameters

Use the existing `current_default_sparse_activity` variant from `run_snn_search.py`:

```text
hidden_neurons = 6
input_weights =
  channel 0: [4, 0, 0, -1, 2, 0]
  channel 1: [0, 3, 0, -1, 2, 2]
  channel 2: [0, 0, 4, -1, 0, 2]
  channel 3: [-1, -1, -1, 6, -1, -1]
output_weights = [-1, 0, 1, -2, 1, 1]
```

Use the same inference semantics as the existing tiny_snn_v2 RTL:

- leak and clip before adding drive,
- clip after adding drive,
- reset hidden membrane on spike,
- fixed integer membrane values,
- no training.
